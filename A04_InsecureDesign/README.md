## 📋 Опис

Інтерактивна лабораторна робота для вивчення вразливостей **OWASP Top 10 2021 - A04: Insecure Design** (Небезпечне проєктування). Додаток умисно містить множинні вразливості для навчальних цілей.

## 🎯 Навчальні цілі

- Розуміння принципів небезпечного проєктування

- Дослідження IDOR (Insecure Direct Object References)

## 🔥 Вразливості

### 1. **Небезпечне скидання пароля**
- ❌ Токени генеруються предикабельним способом (SHA256 від email+username)
- ❌ Токени не мають реального терміну дії
- ❌ Токени можна використовувати необмежену кількість разів
- ❌ Старі токени не інвалідуються

### 2. **SQL Injection**
- ❌ Відсутня параметризація запитів у функції логіна
- ❌ Можливість обходу автентифікації через `' OR '1'='1`

### 3. **IDOR (Insecure Direct Object References)**
- ❌ Відсутня перевірка прав доступу до профілів
- ❌ Можливість перегляду даних будь-якого користувача

### 4. **Відкритий доступ до API**
- ❌ Ендпоінт `/api/users` повертає всіх користувачів з паролями
- ❌ Ендпоінт `/api/tokens` показує всі токени скидання
- ❌ Відсутня автентифікація для API

### 5. **Слабке зберігання паролів**
- ❌ Паролі зберігаються у відкритому вигляді
- ❌ Відсутнє хешування та сілінг

### 6. **Слабка генерація Session ID**
- ❌ MD5 хеш від username + timestamp
- ❌ Предикабельний та вразливий до брутфорсу

### 7. **Відсутня валідація вводу**
- ❌ Немає перевірки складності пароля
- ❌ Немає перевірки формату email
- ❌ Відсутня захист від CSRF

## 📝 Практичні завдання

### Завдання 1: Підбір токена скидання пароля

**Мета:** Змінити пароль адміністратора без знання його поточного пароля

**Кроки:**
1. Відкрийте головну сторінку `http://localhost:3004`
2. У розділі "Підбір токена" введіть:
    - Email: `bob@example.com`
    - Username: `bob`
3. Натисніть "Згенерувати токен"
4. Скопіюйте згенерований токен
5. Перейдіть за посиланням скидання пароля
6. Встановіть новий пароль `hacked123`
7. Спробуйте використати той самий токен ще раз

**Питання для аналізу:**
- Чому можливо згенерувати токен без доступу до сервера?
- Що робить токен предикабельним?
- Які наслідки багаторазового використання токена?

### Завдання 2: SQL Injection

**Мета:** Увійти в систему без знання пароля

**Кроки:**
1. У розділі "Вхід" введіть:
    - Username: `admin' OR '1'='1`
    - Password: `будь-що`
2. Натисніть "Увійти"
3. Проаналізуйте відповідь сервера

**Питання для аналізу:**
- Чому запит виконався успішно?
- Який SQL запит було виконано насправді?
- Як параметризовані запити можуть це запобігти?

### Завдання 3: IDOR Attack

**Мета:** Отримати доступ до даних інших користувачів

**Кроки:**
1. У розділі "IDOR Attack" змінюйте User ID від 1 до 10
2. Переглядайте дані різних користувачів
3. Зверніть увагу, що не потрібна автентифікація

**Питання для аналізу:**
- Які дані можна отримати через IDOR?
- Як перевірка прав доступу може запобігти цьому?

### Завдання 4: Витік даних через API

**Мета:** Отримати повний дамп бази даних

**Кроки:**
1. Натисніть "Завантажити користувачів"
2. Натисніть "Завантажити токени"
3. Проаналізуйте отримані дані

**Питання для аналізу:**
- Які чутливі дані відкриті?
- Чому паролі у відкритому вигляді — це небезпечно?
- Як повинен бути захищений API?

## 🛠️ API Ендпоінти

### Автентифікація
- `POST /register` - Реєстрація нового користувача
- `POST /login` - Вхід в систему
- `POST /forgot` - Запит токена для скидання пароля
- `GET /reset?token=...` - Форма скидання пароля
- `POST /reset` - Підтвердження нового пароля

### Профілі
- `GET /profile/:userId` - Перегляд профілю користувача (IDOR)

### Утиліти (для дослідження)
- `GET /api/users` - Список всіх користувачів
- `GET /api/tokens` - Список всіх токенів
- `POST /api/bruteforce-token` - Підбір токена
- `POST /api/reset-db` - Очистка токенів

## 🛡️ Як виправити вразливості

### 1. Безпечне скидання пароля
```javascript
// ✅ ПРАВИЛЬНО: Використовуйте криптографічно стійкий генератор
const token = crypto.randomBytes(32).toString('hex');

// ✅ Перевіряйте термін дії
if (Date.now() > row.expires_at) {
    return res.status(400).send('Токен прострочений');
}

// ✅ Позначайте токен як використаний
db.run('UPDATE password_reset_tokens SET used = TRUE WHERE token = ?', [token]);

// ✅ Перевіряйте статус використання
if (row.used) {
    return res.status(400).send('Токен вже використаний');
}
```

### 2. Захист від SQL Injection
```javascript
// ✅ ПРАВИЛЬНО: Параметризовані запити
db.get(
    'SELECT * FROM users WHERE username = ? AND password = ?',
    [username, password],
    callback
);
```

### 3. Захист від IDOR
```javascript
// ✅ ПРАВИЛЬНО: Перевірка прав доступу
if (sessionUserId !== requestedUserId && userRole !== 'admin') {
    return res.status(403).json({ error: 'Access denied' });
}
```

### 4. Безпечне зберігання паролів
```javascript
// ✅ ПРАВИЛЬНО: Використовуйте bcrypt
const bcrypt = require('bcrypt');
const hashedPassword = await bcrypt.hash(password, 10);
```

### 5. Захист API
```javascript
// ✅ ПРАВИЛЬНО: Middleware для автентифікації
function requireAuth(req, res, next) {
    const sessionId = req.headers['authorization'];
    if (!sessions[sessionId]) {
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
}

app.get('/api/users', requireAuth, requireAdmin, handler);
```
