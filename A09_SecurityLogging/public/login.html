A09: Помилки журналювання та моніторингу

Вразливість:

Цей додаток НЕ логує критичні події безпеки:

  • Невдалі спроби входу
  • Спроби доступу до адмін панелі
  • Несанкціоновані запити до API
  • Підозрілу активність
Переглянути логи Демо атаки

Завдання:

  1. Тест 1: Увійдіть як alice / alice123. Перевірте логи — чи з'явився запис?
  2. Тест 2 (Brute-force): Спробуйте 10 разів увійти як admin з неправильними паролями (123, pass, admin, qwerty тощо). Потім перевірте логи — чи є там хоч один запис про невдалі спроби?
  3. Тест 3 (Username enumeration): Спробуйте увійти з іменами test1, test2, admin, root та випадковими паролями. Чи може атакувач дізнатися, які користувачі існують?
  4. Тест 4 (Привілеї): Увійдіть як alice, спробуйте відкрити /admin. Перевірте логи — чи зафіксовано спробу несанкціонованого доступу?
  5. Тест 5 (API): Увійдіть як звичайний користувач і спробуйте відкрити /api/users у новій вкладці. Чи логується ця спроба?

Чому це небезпечно?

Без логів атакувач може:

  • Незліченну кількість разів намагатися підібрати пароль (brute-force)
  • Визначити існуючі облікові записи (username enumeration)
  • Намагатися отримати доступ до адмін панелі
  • Красти дані через API без виявлення

І ніхто про це не дізнається! Це класична помилка журналювання з OWASP Top 10.

Як виправити?

Потрібно логувати:

  • Всі спроби входу (успішні ТА невдалі)
  • IP-адреси та часові мітки
  • Спроби доступу до захищених ресурсів
  • Зміни в правах доступу
  • Підозрілу активність (багато невдалих спроб за короткий час)

Плюс налаштувати алерти та регулярний моніторинг!

Тестові облікові дані:

alice alice123 Звичайний користувач
bob bobpass Адміністратор
charlie charlie123 Звичайний користувач
