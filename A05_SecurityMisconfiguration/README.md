# 🔐 A05: Security Misconfiguration — Node.js Лабораторна робота (Версія для МАІКС)

## 🎯 Мета
Навчитися виявляти, експлуатувати та виправляти **неправильну конфігурацію безпеки**, коли **додаток не обмежує кількість запитів** на критичні операції — що дозволяє **брутфорс** або **розкриття email-адрес**.


## 🚫 Вразливість (Умисно вставлена)

У цьому додатку **немає жодних обмежень** на кількість запитів `/forgot`:

- **Немає rate-limiting** (обмеження запитів на хвилину)
- **Немає CAPTCHA**
- **Немає блокування IP**
- **Немає логування спроб**

Це — **неправильна конфігурація безпеки**.  
Це **не помилка коду** — це **відсутність налаштування**.

### Приклад атаки:
1. Атакувач знає, що в системі є користувач `bob@example.com`.
2. Він запускає скрипт, який надсилає **1000 запитів** на `/forgot` з цим email.
3. Сервер **не блокується** — він обробляє кожен запит.
4. Атакувач використовує це для:
    - **Перебору email-адрес** (`admin@*`, `user@*`, `test@*`)
    - **Завантаження сервера** (DoS)
    - **Затоплення поштового сервера** (відправлення 1000 листів)

Це — **A05: Security Misconfiguration** — бо **система функціонує, але не захищена на рівні конфігурації**.

## 🔍 Як виявити?

- Відкрийте `http://localhost:3005/api/attempts` — чи бачите ви список спроб?
- Надішліть 5 запитів з одного email — чи вони зберігаються?
- Спробуйте відправити 50 запитів з `curl` або `Postman` — чи сервер не відповідає 429 Too Many Requests?
- Використайте **Burp Intruder** або **Python-скрипт** для надсилання 100 запитів — чи вони всі успішні?

> **Питання:** Чи може атакувач надіслати 1000 запитів на `/forgot` без блокування?  
> **Якщо так — це A05!**

## ✅ Як виправити?

**Правильний підхід:**  
**Завжди встановлюйте обмеження на критичні операції.**

### Виправлення (`server.js`):

```javascript
const rateLimit = require('express-rate-limit');

// ВИПРАВЛЕНО: Додаємо rate-limit на /forgot
const forgotLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 хвилин
  max: 5, // максимум 5 запитів за 15 хв
  message: { error: 'Too many requests. Try again later.' },
  standardHeaders: true,
  legacyHeaders: false,
});

app.post('/forgot', forgotLimiter, (req, res) => {
  // ... інша логіка — без змін
});
